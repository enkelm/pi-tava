# LiteLLM provider reuse

Research only, 2026-10-11. Installed extension: **pi-provider-litellm 4.2.0**; Coop runtime: **Pi 1.1.0**. No provider activation, credential/environment inspection, inference, tests, installs, source changes or restart. Only this note was written; unrelated working changes were left alone.

Source shorthand (each citation gives an exact file and line range):

- `L/` = `/Users/enkelm/.pi/agent/npm/node_modules/pi-provider-litellm/`
- `A/` = repository `node_modules/@earendil-works/pi-ai/`
- `C/` = repository `node_modules/@earendil-works/pi-coding-agent/`

- Other paths are relative to `/Users/enkelm/Projects/pi-coop/`.

## Bottom line — recommendation

Reuse the **native Provider + discovery implementation**, not the ordinary Pi extension object. The factory is a useful core, **not a complete integration or supported library export**. Extract/publish host-neutral auth/config and request/final-message transformations alongside it, with thin Pi and Coop adapters.

Smallest useful first delivery: explicitly **API-key-only**, stable `litellm` identity plus configured aliases, credential-bound HTTPS roots/custom headers, bounded discovery + cached catalog/explicit refresh, native streaming with cancellation, required payload policies, and request-local cost finalization **before Durable commits**. Expose an optional telemetry capability but allow it to be absent. Do not make budget polling, SSO, dashboard or routing prerequisites. If existing SSO credentials must work on day one, auth extraction is a prerequisite, not an optional follow-up; an API-key pilot is not SSO parity.

## Verified facts

### 1. Accessibility and version compatibility

- `L/package.json:1–32,47–79` declares version 4.2.0, Node >=22.19.0, optional peers `pi-ai`/`pi-coding-agent` >=0.99.2 and development versions ^1.0.3. It publishes `src`, README and LICENSE; **no `main`, `types` or `exports` field**. `pi.extensions` points to `./src/index.ts`. README explicitly says the old library import was removed and source-only distribution is supported only as a Pi extension (`L/README.md:25–33`).
- Source-level exports exist: `createLiteLLMProvider`, its options, `toNativeModels` (`L/src/provider.ts:18–45,139`); discovery (`L/src/discover.ts:1161`); `pollBudget`, `mergeKeyHeaders` (`L/src/budget.ts:155–156,221`); types (`L/src/types.ts:1–97`); and `prepareLiteLLMRequestPayload` from the extension entrypoint (`L/src/index.ts:1701`). **`createProviderAuth`, settings/credential resolution and SSO helpers are private** (`L/src/index.ts:96,114,500,588,1315,1369,1454,1531`). Exported functions inside source files are not a supported package-root API.
- No exports map forbids deep source paths, but that does not make them native-Node-compatible: factory/discovery use local `.js` specifiers while the installed package contains `.ts` sources, not corresponding built `.js` files (`L/src/provider.ts:13–16`, `L/src/discover.ts:1–40`). A filesystem search found **no `.js`, `.mjs` or `.cjs` files** anywhere in this installed package (only root and `src` directories). Independently, [official Node v24 documentation](https://nodejs.org/docs/latest-v24.x/api/typescript.html#type-stripping-in-dependencies) explicitly refuses TypeScript files under `node_modules`. Thus even a deep `.ts` path is not a plain-Node loading solution. Ordinary Pi loads through Jiti with host-package aliases; Coop's extension loader uses native `import(url)` and calls `default(PocketHost)` (`C/dist/core/extensions/loader.js:33–77,472–482`; `src/server/reload.ts:325–355`). Direct imports/reproductions were not executed. Prefer a proper shared **JavaScript library entry**; do not switch the whole Coop launcher to tsx solely to load this extension's internal sources.
- Semver requirements overlap Coop's Node >=22.19 and Pi 1.1.0 pins (`package.json:20–21,51–56`). Relevant native interfaces and `pi-ai/compat` are present (`A/package.json:13–39`; `A/dist/index.d.ts:20–32`; `A/dist/compat.d.ts:12–37`). The extension also checks Pi >=0.99.2 during activation (`L/src/index.ts:1876–1885`). **This establishes nominal API compatibility, not verified runtime/loading compatibility.** `compat` is explicitly temporary (`A/dist/compat.d.ts:1–10`); pin/support an actual version range and bind shared modules to the host's dependencies, not a second Pi runtime resolved from a global installation.

### 2. What the factory does — and omits

- Factory inputs require caller-supplied `ProviderAuth`, credential-root resolver and discovery callback. It converts models to protocol-specific roots, guards cached/active root equality and placeholders, filters availability, caps OpenAI Chat tool count, dispatches three native APIs, and repairs/enriches cached discovery-policy metadata (`L/src/provider.ts:18–45,59–137,139–263`; `L/src/protocols.ts:11–42`). This is substantial reusable behavior.
- The ordinary entrypoint supplies global-only settings, alias definitions, credential precedence, custom header resolution, offline/timeout gates, bounded startup seeds, OAuth token-to-root state and additional refresh synchronization (`L/src/index.ts:96–132,348–435,437–538,1974–2185`). **None is automatically supplied by importing the factory.** Its protocol APIs also do not install Pi event hooks (`L/src/protocols.ts:35–42`).
- Aliases are provider IDs with their own base URL/key/header config and auth-store entry. Only default `litellm` enables interactive API-key login, OAuth/OIDC and Google ADC; aliases use configured or manually stored credentials (`L/src/index.ts:500–538,1539–1547,1611–1634`; `L/README.md:172–174`). Preserve existing IDs so imported/resumed model references and stored credentials remain resolvable; do not merge aliases merely because their URLs match.
- API-key login returns `{type:"api_key", key, env:{LITELLM_BASE_URL}}`. Resolution pins `auth.baseUrl` to the active credential root, including special handling of an OAuth token round-tripped as an explicit API-key override (`L/src/index.ts:588–593,1454–1529,1582–1610,2125–2155`). This protects against stale/off-catalog model hosts. Runtime composition can fall back to a global API for an API absent from the base provider catalog, so root pinning **and** guard/transform coverage on custom-model paths matter (`C/dist/core/provider-composer.js:372–388`).
- SSO is much more than a bearer-token reader: direct configured OIDC, proxy CLI-auth PKCE, legacy `/sso/cli/start` polling, then pasted-token/virtual-key fallback; expired token refresh/relogin, token rotation and transient backoff (`L/src/index.ts:672–1001,1013–1165,1167–1440`). PKCE/OIDC loopback callbacks require a browser on the server's machine (`L/README.md:50–94`). Coop's remote browser prompt/notification bridge is not proof those flows work remotely (`src/server/providers.ts:55–109`).
- Shared native auth already persists rotated OAuth under a credential-store lock, with refresh surviving caller cancellation to avoid losing a rotated token; stored credentials do not silently fall back to ambient auth (`A/dist/auth/resolve.js:4–39,49–100`). Reuse that host mechanism. Do not copy secrets into telemetry or invent another auth store.
- Pi hooks add session correlation, important deployment-driven payload repairs, fallback diagnostics and final think-tag normalization (`L/src/index.ts:1701–1874,2259–2295,2326–2335`). Factory-only streaming omits all of these. Adapt required request policies through `onPayload`, final normalization through the stream wrapper, and `x-litellm-session-id` from `options.sessionId`. Durable supplies session ID/signal to generation and compaction (`D/dist/harness/generation.js:113–121`; `D/dist/harness/compaction.js:119–129`). MCP, Skills Gateway and Pi UI/commands are separate optional integrations, not transport requirements (`L/src/index.ts:1918–1972,2236–2257,2297–2324`).

### 3. Catalog/pricing refresh is reusable, but initialization needs an adapter

- Discovery prefers `/model/info`, expands wildcard routes using `/v1/models`, and falls back on 401/403/404 to `/v1/models`, then older `/health` routes. It preserves deployment evidence rather than guessing every protocol from route names (`L/src/discover.ts:1161–1316`). Keep the reducer/dependency closure (`model-groups`, backend identity, protocols, thinking levels, public catalog, proxy version), not a new simplified model-name parser.
- Explicit proxy rates are per-token converted to per-million; route groups conservatively use highest known rates and lowest limits, intersect capabilities, preserve relevant pricing tiers, and use **zero for unknown price fields**. Discovery's presentation marks incomplete metadata, but does not publish a structured price-provenance/unknown flag (`L/src/model-groups.ts:633–653,823–883,955–975`; `L/src/discover.ts:782–805,823–847`; `L/src/types.ts:47–70`). Zero rates therefore cannot mean proven free usage. Enrich metadata if later telemetry/router decisions need that distinction.
- Pi's embedded catalog is a fallback; models.dev enrichment is opt-in in the entrypoint. Calling raw discovery without those options changes behavior: its catalog loader can consult models.dev by default (`L/src/index.ts:460–477`; `L/src/discover.ts:596–607`; `L/src/public-catalog.ts:232–281`). Pass explicit offline/enrichment/cache policy; no unrequested third-party metadata refresh.
- `createProvider` restores stored models, publishes fetched catalog + `checkedAt`, and retains prior dynamic state on failed fetch. Pi-ai generation-checks publications and aborts superseded refreshes (`A/dist/models.js:120–172,527–603`). The LiteLLM wrapper restores versioned policy and prefers current seed over incompatible legacy cache entries (`L/src/provider.ts:222–262`). It does not establish a pricing refresh cadence.
- Coop creates `ModelRuntime` and calls a synchronous `configureModels` callback before loading Durable modules. Registration triggers only asynchronous **cache-only** refresh; login also synchronizes cache-only. No LiteLLM catalog seed/network refresh appears automatically (`src/server/app.ts:257–260`; `C/dist/core/model-runtime.js:95–107,398–417,627–635`). Plan an awaited, bounded startup/cache initialization and explicit network refresh after login/on demand, honoring offline policy. Current synchronous injection option is not a production async module loader.
- Native registration replaces by ID; unregister recomposes the underlying provider. It does not dispose module-owned pollers/SSO servers/state (`C/dist/core/model-runtime.js:627–635,676–681`; `A/dist/models.d.ts:65–128`). Durable modules have a different ABI. Shared installation needs owner-approved configuration, explicit ownership/disposal and deterministic registration before resume; hot-reload parity can wait.

### 4. Cost header accounting can happen before persistence

**Yes, structurally.** All three HTTP transports invoke `onResponse` before consuming the stream, then return normalized terminal messages. `StreamOptions` supports both `onResponse` and `onPayload` (`A/dist/types.d.ts:54–85,113–123`; `A/dist/api/openai-completions.js:188–203,488–513`; `A/dist/api/openai-responses.js:124–171`; `A/dist/api/anthropic-messages.js:429–444,675–686`).

Recommended adapter: wrap both native `stream` and `streamSimple`; capture a finite nonnegative response charge in a **per-request closure**, chain caller callbacks, preserve signal/options, and finalize terminal `done`/`error` message usage before forwarding it and resolving `result()`. A real `AssistantMessageEventStream` makes terminal events and `result()` agree (`A/dist/utils/event-stream.js:35–46,87–115`). Do not merely mutate an event after it was forwarded or only update a UI observer.

- Existing `setupLiteLLMCostTracking` instead installs ordinary Pi events and keeps one pending cost **per provider**. That is not safe for simultaneous Coop conversations using the same alias; it also accepts loose `parseFloat` values and invents component allocation proportional to tokens (`L/src/cost.ts:3–51`). Reuse the precedence idea, not this state map/parser or a claim that proportional components are provider-reported prices.
- Durable generation takes `events.result()` and commits assistant entry + usage together; compaction separately commits its returned usage (`D/dist/harness/generation.js:294–304,523–529`; `D/dist/harness/compaction.js:128–139`; `D/dist/harness/usage.js:13–38`). A provider-side wrapper covers both, unlike an ordinary Pi `message_end` hook. Valid response cost should **replace**, never add to, the local estimated total for the same request. Keep the estimate/source separately if needed; absent/invalid header keeps the estimate, marked unknown where prices are unknown.
- A header is **not guaranteed final streaming cost or an invoice**. Official LiteLLM source at [commit 2a01fe6](https://github.com/BerriAI/litellm/blob/2a01fe6e5ca2ed67472ca0ed2909e66811ff8d35/litellm/proxy/common_request_processing.py#L2510-L2538) builds streaming headers from `hidden_params.response_cost` or an empty string; [lines 2805–2836,2955–2963](https://github.com/BerriAI/litellm/blob/2a01fe6e5ca2ed67472ca0ed2909e66811ff8d35/litellm/proxy/common_request_processing.py#L2805-L2836) assemble them before streaming. [Lines 1875–1936](https://github.com/BerriAI/litellm/blob/2a01fe6e5ca2ed67472ca0ed2909e66811ff8d35/litellm/proxy/common_request_processing.py#L1875-L1936) show key-spend is a cumulative account figure, not this request's charge. This current upstream source is not evidence of the deployed proxy's version/behavior. Do not promise complete streaming-charge recovery from headers alone.
- Coop sums usage totals and attributes **positive deltas only** to the requester current at that commit (`src/server/projection.ts:457–466`; `src/server/spend.ts:96–122`; `src/server/app.ts:433–440`). Late revisions would charge today's requester; decreases do not refund person totals. Keep delayed/revisable provider account observations **outside existing spend enforcement**. Do not retrofit a reconciliation ledger in milestone 1 or add budget-spend deltas to request costs.

### 5. Budget poller reuse requires enrichment, not just mapping

`pollBudget` is an exported host-neutral HTTP utility. `setupLiteLLMBudget` is Pi UI/lifecycle code (UI-only polling, delayed turn refresh, timer/shutdown handling); do not reuse that setup in Coop (`L/src/budget.ts:155–205,326–335,375–435,470–537`).

The utility already handles key/user/team/member/org scopes, old user endpoint fallback, denied endpoints, transient retention and JWT team ambiguity (`L/src/budget.ts:48–205`). **Its output does not meet honest normalized telemetry semantics:**

- `BudgetLevel` has only spend/limit/reset. Missing/invalid spend becomes **0** when a positive limit exists; absent/nonpositive limit drops the level entirely (`L/src/budget.ts:11–18,31–40`). This conflates unknown spend with zero, and absence with no budget/unreadable/unknown.
- Transient user/team/org failures retain prior values, but final `ok:true` loses per-scope stale/error status and sample time. IDs are read for endpoint selection, then discarded from returned levels (`L/src/budget.ts:73–205`). A successful overall poll cannot honestly stamp retained scopes as fresh.
- Header merging only raises key spend against last poll and is not a general reset/revision mechanism (`L/src/budget.ts:221–233`). Denial caching resets on credential/header identity change or manual refresh in the Pi adapter, not in the poller itself (`L/src/budget.ts:367–419,541–545`). The poller has a timeout argument, not a caller AbortSignal (`L/src/budget.ts:48–60,155–160`).

**Recommendation:** extract/enrich parsing and polling to return per-scope known/unknown/unavailable/stale state, source endpoint/header, observation time (last successful time for retained data), stable opaque pool identity and membership/enforcement certainty. Preserve missing spend as unknown; distinguish no configured limit from denied/unknown. Include cancellation and credential-change invalidation. Expose server-owned opaque key/user/team/org IDs, never keys, raw headers, team names or whole proxy responses. A salted auth digest is a cache invalidation mechanism, **not** a stable shared-team identity: aliases can share a team while using different keys. Until identity can be established, do not aggregate aliases or claim multiple remaining balances are independent pools. Budget enforcement itself varies with proxy settings (`L/README.md:220–243`).

## Optional telemetry minimum — recommendation, not existing API

A provider module may omit telemetry; a companion telemetry-only module may use the same host-resolved auth. Its absence/failure must not disable healthy inference. Minimum observations should include:

- provider ID + opaque account/pool scope; optional model/request reference;
- kind/unit/currency: recorded tokens/requests, rate estimate, provider-reported request charge, cumulative account spend, limit/remaining/reset;
- source and sampled time, known/unknown/unavailable/stale state, last-good time where applicable;
- charge finality/revision and idempotent identity for any delayed observation; scope sharing/enforcement certainty.

Keep token counters, estimate and provider charge as alternative views of one request, not three billable amounts. Shared pools appear once; parent budgets and member/key budgets are constraints, not additive balances. Router/dashboard receives redacted normalized observations, not auth. Initial module can return no budget capability until enriched polling exists.

## Explicitly defer

- SSO/PKCE/OIDC/legacy pasted-token flows in an API-key pilot; ADC and shell key helpers unless specifically required. Preserve stored SSO data untouched and report unsupported auth rather than silently using an env key.
- Pi MCP/Skills Gateway, footer/commands and a general `ExtensionAPI` shim.
- Budget UI/CLI, background multi-scope polling until enriched, late invoice/request reconciliation, classifier routing and quota-based automatic fallback.
- Broad hot-reload compatibility; begin with deterministic startup install/unregister/dispose semantics. Do not silently change active/resumed work to another provider.

## Blockers / unresolved issues

1. **Packaging:** choose supported compiled JavaScript/subpath exports upstream or a separately versioned extracted core. No usable public JS entry/compiled output is installed, and Node blocks type stripping under node_modules. An ad hoc deep import from this global source-only package is not a production dependency strategy.
2. **Auth boundary:** factory alone cannot reproduce existing saved SSO, alias settings, root pinning or request policies. Decide API-key pilot versus full existing-login compatibility before promising milestone completion.
3. **Initialization/lifecycle:** settle an async registration seam before harness resume, refresh after login, disposal and failure semantics for unavailable resumed providers. Registration alone does not fetch models or dispose work.
4. **Accounting evidence:** validate deployed proxy header behavior, parallel same-provider streams, compaction, cancellation/error usage and terminal event/result consistency using future isolated scripted transports. No such validation ran here. Missing streaming headers/unknown catalog rates must remain explicit limitations.
5. **Telemetry truth:** current BudgetPoll cannot recover per-scope identity/freshness/unknowns from its reduced return value. Enrich below that boundary or leave telemetry absent; do not mask it with an `observedAt:now` adapter.
