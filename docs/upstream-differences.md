## Validation and remaining risks

The implementation thread recorded passing `npm run check`, `npm run lint`, changed-file Prettier checks, `git diff --check` and syntax checks for the changed browser modules. Focused evidence includes **86/86 integration tests**, **21/21 final delivery tests** (including late asynchronous header rejection) and **2/2 MCP/session-list regressions**. These are overlapping focused runs, not a full-suite total. Dependency inspection and a disposable drop-in import confirmed one shared `McpClient` implementation. Regression checks also demonstrated failures before the relevant changes for checkpoint replay, transcript rescanning, live bytes and delivery.

Useful local implementation logs are `/tmp/coop-perf-final-focused.log` and `/tmp/coop-perf-full-tests.log`. They are temporary evidence, not permanent artifacts or an independent review. Temporary paths may disappear; the review and landing results below retain the relevant conclusions.

The full suite is **not green**. `npm test -- --test-timeout=60000 --test-concurrency=4` timed out after 420 seconds without a final summary. Broader runs encountered listener `EPERM`, watcher `EMFILE` and unavailable process-fingerprint inspection; other failures remain unclassified. Five `visible-clock` failures involving an absent `location` were reproduced on unchanged `HEAD`, but that baseline result does not explain all full-suite failures. New Markdown/sidebar browser tests timed out after 90 seconds and remain unvalidated. This documentation pass did not retry those unavailable checks or the full suite.

Fixture measurements support narrower claims: synthetic live growth used **22,239 delta bytes versus 211,821 whole-message bytes**; the stylesheet compressed from **381,606 bytes to 66,894 Brotli / 72,619 gzip**. Stream tests exercised pending-input limits, stalled-reader timeout and cleanup. These are not real-device or tunnel-latency benchmarks. Safari/iPad rendering, actual tunnel behavior, startup speed and battery effects remain unverified.

The independent Reviewer episode assessed the complete uncommitted delta against `05ceef65e053d54135c2ea833fc5ced333934a01`, including protocol recovery/send ordering, asynchronous HTTP completion and shutdown, checkpoint/fork contracts, cached attribution versus fresh authority, Markdown/sidebar code and the ledger's local-source provenance. It found and repaired one negotiation defect: an explicit higher `identity` quality was ignored in favor of compression. The existing HTTP negotiation test failed for the intended reason before the repair and passed afterward. No other actionable introduced defect remained from that inspection; this is not a full-suite or browser/device pass.

Independent validation passed `npm run check`, `npm run lint`, changed-file formatting/syntax checks, **31/31** delivery/storage/attribution tests, **38/38** project/SSH authorization and workspace-read lifecycle tests, and the focused **1/1** MCP drop-in import test. A separate protocol/app/navigation/projection/lifecycle run passed **49 tests** and failed **10 listener-based app tests**, all with `listen EPERM`; those unavailable listener checks were not retried. These results do not explain the implementation thread's other unclassified broader failures. The Markdown/sidebar browser tests, full suite, docs-site build and device/tunnel measurements remain unavailable or deferred as recorded above. The attribution LRU bounds conversation count, not bytes or facts within one long conversation. Passing focused checks does not authorize deployment.

The documentation-only completion passed local link/anchor and Pocket/Coop commit-reference checks, scoped Prettier, sidebar ESLint/syntax, the standalone docs reference checker and `git diff --check`. The full docs-site build was not run because its Astro dependencies are not installed. External links and the pre-existing Collie/GPUI revision claims were not revalidated online.

1. At each intake, record the date, exact fork/upstream refs and merge-base before classifying changes. Distinguish locally available source from live release/API evidence. Link the intake thread or retained assessment; keep the original starting-point and license provenance in `FORK.md`.
2. Update the existing aspect rows here instead of keeping another "current" table in `FORK.md`, a handoff or a research note. Split a row when only part is adopted. Record the owner's actual selection separately from recommendations, with a reason and revisit condition for deferred work.
3. On adoption or removal, replace provisional source references with the fork commit/review reference, relevant code/docs and actual validation. Keep upstream source commit IDs. Mark local implementation, independent review, commit and deployment as separate facts; never advance a status from intent alone.
4. Reconcile old deferred/removed rows against current code and history, including ancestry changes. Preserve historical notes as historical. Update [map](map.md), [architecture](architecture.md), [features](features.md), [security](../SECURITY.md) or the relevant feature guide if its contract changed.
5. Check Markdown links/formatting and the docs reference checker. New pages need [sidebar registration](../docs-site/src/sidebar.mjs). Run the docs-site build when its dependencies/capabilities are available; record missing checks rather than fetching, restarting or publishing without authorization.

Future intakes should remain selective. A release label, clean textual merge or upstream test pass does not establish compatibility with Coop's private routes, SSH capabilities, workflow or publication policy.
