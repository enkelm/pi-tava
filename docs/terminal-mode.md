# Structured Herdr Terminal mode

Structured Terminal is implemented, with the parity limits listed below. The goal is Herdr GPUI's terminal and navigation behavior in the browser, not a claim that every native feature already works. The user chose this approach over the smaller ANSI/xterm bridge.

## Desktop and mobile

Private desktop views default to Terminal. The sidebar follows GPUI's compact Spaces/workspaces and Agents lists; tabs belong above the terminal area. Desktop operation is keyboard-first. An action dropdown must not replace Herdr's bindings. A shortcuts reference can explain bindings and browser limits.

Mobile defaults to agent Chat. Verified idle Pi panes also offer native slash-command completion, a model picker and private uploads in Chat. Files are delivered as server paths for Pi's tools to read; they are not native clipboard image events. Built-in terminal dialogs and multiline or shell input still require Terminal. A model command may open a selector if that model is not available to the target Pi, so Chat waits for saved model reflection or an explicit editor check. See [private-sessions.md](private-sessions.md).

Terminal remains available, with a full touch keyboard instead of a hotkey bar. It has QWERTY letters, a number row, symbols, F1–F12, Esc/Tab, editing and navigation keys. Ctrl, Alt, Cmd/Meta and Shift apply to the next key; a second tap locks a modifier and a third releases it. Arrows, Delete and Backspace repeat while held. The bottom-right footer groups Touch and Native as a persistent keyboard-type selector, with an adjacent chevron to collapse or expand the selected keyboard. Collapsing Touch gives its space back to the terminal; collapsing Native blurs and suppresses device text input until explicitly expanded. The keyboard toolbar keeps the layout tabs. The mobile quick-action bar retains Previous tab, Next tab, New tab, Split and Zoom; a Paste icon at its far right is visible only in Touch/UI keyboard mode. The footer type selector remains available in Native mode to switch back. Only the always-visible modifier hint is removed; modifier instructions stay in Help. In very short views, key rows scroll beneath the layout controls rather than being clipped. Swiping over the keyboard cancels pending taps; letters and modifiers activate on release, while deliberate holds repeat editing/navigation keys. In the pane itself, one-finger swipes scroll rather than selecting text or starting an application mouse drag. Hold for 450 ms, then drag, to select locally; a small pulse at the hold point confirms activation without moving the pane. Reduced motion uses a static cue. A short tap still clicks mouse-reporting applications, and pinch zoom remains browser-owned. Touch scrolling has no queued momentum after release. Keyboard and assistive-tech activation preserve key-button focus for Tab navigation. Touch input suppresses the native keyboard by default; the Native segment explicitly enables it for IME or other input, and the Touch segment switches back. Paste opens an editable text field for the phone’s native paste menu, then Paste into pane sends one semantic paste without an extra Enter. It needs no browser clipboard permission. Cancel clears the text; changing the pane, popup, connection or access discards it. The same 1 MiB UTF-8 limit applies as for hardware-keyboard paste. Desktop hardware input and Herdr bindings stay unchanged. Touch shortcuts use the same Herdr keymap, and modifiers/repeat clear on target, popup, connection or access changes. Do not squeeze a desktop split layout into a phone or make a mobile user operate every agent through terminal keystrokes. Public sessions keep Pocket's existing interface.

Opening Terminal connects automatically. The user chose this persistent behavior over the initial Connect confirmation screen. Keep one connection per opened Herdr instance across pane, tab and Chat navigation. Background views retain the connection and use `client_shell.surface.set` to suspend unnecessary frames. Wait for its response before considering surface interest changed. Transport loss can reconnect to fresh state, never replay old keystrokes or requests. Explicit disconnect and owner-access loss stop reconnection. Browsers, especially iOS in the background, can still suspend or close a socket.

Connecting can resize shared panes or resume a pending agent. Viewport geometry is deduplicated for the mounted grid and connection epoch, across metadata/surface availability gaps; an unchanged viewport is not repeatedly resized just because painting/input resumes. Real viewport or cell-metric changes and fresh connections still report geometry. Explain this in compact status/help text rather than a blocking banner. Closing the connection detaches the web client; it does not stop the shell or Pi. Closing a pane, tab or workspace is a separate, confirmed operation and is never an import side effect.

## Implementation

```text
owner browser
  -> authenticated, origin-bound one-use WebSocket ticket
  -> Node private terminal gateway
  -> owned native helper child with JSON-line stdin/stdout
  -> pinned Herdr GPUI client and structured binary endpoint
  -> existing Herdr daemon and PTYs
```

`src/server/private-terminals.ts` owns connection tickets, live authorization, target validation, queue bounds and helper lifetimes. `POST /api/private/:id/terminal` requires the owner, `X-Pocket: 1`, valid geometry and `acknowledged: true`. It returns a 30-second ticket for `/api/private-terminal`. The upgrade checks the current owner credential, exact origin and the ticket before touching an endpoint. Tickets are consumed once. A selected pane's terminal identity is checked again before launch.

The server derives `herdr-client.sock` from its own discovery result. A browser cannot choose a filesystem socket or executable. The endpoint must be a same-owner socket. The gateway launches the helper with an argument array, never a shell command.

`native/herdr-web` reuses `herdr-client` and `herdr-protocol` from Herdr GPUI revision `e370bf0a55b1bf3e7e7fcb5b3f130ebc1a9e68bf`. Cargo.lock pins transitive dependencies. The native client owns binary framing, handshake, boot/projection checks, patch reconstruction, graphics decoding and ordered writes. See its [README](../native/herdr-web/README.md) and [JSON contract](../native/herdr-web/interface.ts).

`web/terminal-grid.js` renders structured cells, cursor and graphics using browser APIs. `web/terminal-keyboard.js` owns the touch layouts, one-shot/locked modifiers and bounded key repeat; the grid routes its keys through the current target and shortcut handler. It sends semantic keys, committed text, paste and mouse events. There is no browser VT parser, xterm.js or libghostty dependency. Private frame data never enters a shared Durable room or browser storage.

## Build

The pinned Rust crates require Rust 1.96. With the named toolchain installed:

```sh
npm run build:terminal
npm run test:terminal-native
```

The script uses the named toolchain without changing the global default. The result is `native/herdr-web/target/release/herdr-web`. A missing helper produces a build instruction rather than falling back to raw shell commands or a different transport. Production server changes still require an owner-requested restart after validation. Do not restart the server during an agent's tool call.

## Safety and input semantics

- At most four terminal connections and sixteen pending tickets. Input/output have explicit size and queue bounds; a slow connection closes rather than skipping dependent protocol data or replaying input.
- Owner access is checked for every command/event and on a periodic heartbeat. Token rotation closes a live connection.
- Only supported native methods are forwarded. Targets must belong to the connection's current snapshot. Configured commands must be advertised by that Herdr instance.
- Terminal mode intentionally controls shells and non-Pi applications. It does not promise that input reaches one previously identified Pi PID.
- A helper queue admission is not an acknowledgement that a foreground process consumed input. No command is automatically retried or replayed after reconnect.
- An attached terminal and previous terminal input do not block import. Attachment reserves the shared operation lock through the native handshake and initial focus, not the connection's lifetime. Runtime resize, layout/focus changes, native input, Chat submissions and takeover use short reservations; state-changing terminal operations are refused while the selected pane is moving. Import preview does not disconnect the browser's terminal. Separate Herdr transports still provide no atomic PTY-delivery guarantee, and no queue cancellation is implied. Busy Pi requires explicit confirmation before Escape aborts its work, followed by verified idle/child-exit checks and stopping that Pi alone.
- Unknown Chat prompt delivery has a separate durable receipt and blocks further Chat sends as well as takeover. Receipts store opaque identifiers and timestamps, never transcript or prompt text.
- Temporary owner diagnostics are available in Terminal Help → Copy diagnostics for the idle scroll-jump investigation. They retain only bounded in-memory control/surface metadata (resize/focus activity, geometry, exact scroll offsets and relative timestamps), with aliased identifiers, no terminal/key/clipboard/image values, paths or titles, and no automatic upload or storage. The trace keeps at most 100 event records and samples 16 visible panes; exports are capped at 32 KiB, coalescing content-only frames. Export is an explicit snapshot with a selectable fallback if clipboard writes fail. Access loss or connection disposal clears the trace. Counts describe structured browser-connection activity, not process delivery acknowledgements or every server-side RPC effect. In particular, pane-detail HTTP polling is a separate path: it now uses only passive visible snapshots, never the recent-history read that can make Herdr scroll an alternate-screen application. See [the polling investigation](research/herdr-passive-pane-reads.md).
- Clipboard writes and links require an explicit user action. Never open URLs, read local paths or execute instructions from terminal output. PNG clipboard input is bounded to 8 MiB and 4096 by 4096 pixels in the gateway.

## Parity and verification

| Area               | Current implementation and limits                                                                                                                                                  |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Transport          | Pinned structured client, full/patch reconstruction, exact large identifiers, images and popup frames. Synthetic binary tests cover these separately from the browser gateway.     |
| Desktop navigation | Keyboard bindings, native workspace/tab/pane navigation and a retained instance connection. HTTP discovery includes native navigation IDs alongside opaque route IDs.              |
| Focus and mouse    | Navigation retains typing focus. First-click input does not need an activation click. Browser-side activation borders are removed; Chat, dialogs and IME retain their focus rules. |
| Recovery           | Fresh authenticated connection after transport failure. No old keys, requests, composition or pending image paste may cross the connection epoch.                                  |
| Rendering          | Structured colors, styles, cursors, selection, wide cells and bounded graphics. Browser font shaping differs from GPUI; native exact `cell_widths` are not currently emitted.      |
| Graphics controls  | RGB/RGBA/PNG display and explicit PNG paste. Inline graphics controls remain unsupported.                                                                                          |
| Layout controls    | Native focus, split, zoom and tab/workspace actions. Dragging split dividers and scrollbars is not implemented.                                                                    |
| Key profiles       | GPUI defaults and the supported normalized server profile, including prefix chords. Arbitrary TOML and GPUI-local configuration files are not imported.                            |
| Native-only UI     | Browser-reserved keys, native windows and native search/worktree dialogs do not have full parity.                                                                                  |
| Mobile             | Chat-first Pi workflow and a full collapsible Terminal touch keyboard with desktop modifiers. Real iOS Safari remains unverified.                                                  |
