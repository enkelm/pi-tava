# Security

## Reporting a problem

Please report security problems privately through GitHub: on this repository, open **Security → Report a vulnerability**. Do not open a public issue. Include what you found, how to reproduce it, and what an attacker gains.

## What Pi Pocket protects, and what it does not

Pi Pocket runs a coding agent that executes commands on the machine it runs on, as the user who started it.

- **Signing in.** The owner's sign-in link is the key to the server. Invites are one-time links that expire after 15 minutes, or an hour, a day, or a week when whoever makes one picks that; the longer one lasts, the longer a link that leaks can be used. Their codes are stored hashed. An owner invite, which only the owner can make, always lasts 15 minutes and gives the device that opens it the owner token itself, and with it full control; starting with `--rotate-token` signs out every device that has it and ends owner invites not yet used. Tokens are random, stored hashed, and kept in an `HttpOnly` cookie.
- **Viewers** can read, react, and chat. In sessions they can see, they can read live uncommitted changes within the session folder and comment on changes, files, or lines, even while Pi works. This review-only access does not unlock the Files browser, editor, ordinary Changes routes, tool approvals, or prompting Pi. Comments keep their original author, working folder and optional client-supplied line excerpt; anchors are advisory, not saved snapshots or proof of current file content. Review status follows each original author's unresolved threads, not assigned verdicts. The owner can resolve or reopen any chosen threads in one atomic action; other people can resolve or reopen only their own. Comment and resolution actions recheck current membership and scope, require durable retry IDs, and never drive Pi or Git. Explicit bot buttons send one reviewer's feedback or all feedback through the ordinary submission route, with steering/driver checks and durable retry IDs; viewers cannot use them. Live review diffs accept only listed changed files inside the session folder, excluding renames across its boundary. A review-only context endpoint supplies complete UTF-8 text up to 512 KiB for those changed files, with read-only, no-follow identity checks; it rejects symlink escapes, binary or incomplete reads and does not grant general file access. Forks start without review threads.
- **Anyone who can steer can do what you can.** Through Pi, they reach your files, Pi Pocket's settings and tokens, and its code. An invite to one session limits what someone sees in the app, not what Pi can reach. Neither do git worktrees or spend limits: a worktree keeps a session's files apart, and a run is stopped only after the request that crosses its limit.
- **Approvals.** Lancet Guard approvals can come from anyone who can steer, including the person who asked, unless the owner turns on "Approvals need someone else" (Menu → Extensions); then, when nobody is known to have asked, only the owner can allow. A notification offers Allow only for a call that fits on one short line; anything longer opens the app first. A "Done when" check command runs after every answer without asking, so with Lancet Guard on it must be one the guard allows outright.
- **The built-in browser** reaches what this machine reaches: `localhost`, your network, and the internet. Anyone who can steer can use it from the Browser panel, and Pi from its `browser` tool; Lancet Guard does not check either, and pages can hold whatever they show. The addresses people open show in the session's chat. Its pages run in Chromium on the server and do not automatically share your app tab's cookies. Imported app-authentication cookies are stripped before opening shared pages; do not sign into Pi Coop as the owner inside the shared browser. Only the owner opens files from the address bar or sees which servers run on the machine. If steering guests should not reach your network, turn Browser off in Menu → Extensions. The clean default uses isolated temporary sessions. Only the owner can import a local Chromium-family profile and select it as the app-wide default, with explicit confirmation: its copied cookies and site storage persist and are shared across conversations. Pi and people using the app browser can then access those signed-in accounts; imported profiles are not an owner-only browsing boundary. Import leaves the source unchanged and excludes password/autofill databases and extensions, but cookies and site storage are still credentials. Returning to clean sessions deselects the import, not an erasure of its app-owned copy.
- **File edits and language servers.** Quick saves require steering and the wheel while taking turns, reject stale file revisions and respect session-scoped paths. The route does not write Pi's settings or app state. Unsaved recovery drafts live in the browser tab's session storage until saved or explicitly discarded. Only the owner starts or talks to language servers: these are local processes with the daemon's filesystem and network access, not sandboxes. The bundled TypeScript 7 native server and fixed supported executables on PATH are allowed; browser/project-supplied launch commands and LSP command execution are not. Formatting changes the unsaved browser buffer only. Lancet Guard does not check editor saves or language-server activity.
- **Models** are a person's to choose. Background subagents inherit their parent's model unless another is selected explicitly; an empty owner list (Providers → Models for subagents) leaves explicit choices unrestricted, while a nonempty list limits extra choices. Agent Teams always treats that list as an extra-model allowlist, so empty means parent-only; PiP passes a model only when its person named it; compaction and PiP summaries use the session's own model. Coop's session-title and goal naming use the cheapest available text-capable small model from the same provider, falling back to the session's own; their usage counts toward the session's spend. Subagents on another model, and PiP, ask a model's sign-in afresh first and use none whose sign-in expired; a session's own run, a subagent on its model, titles, and summaries just try the model, and a run that fails on an expired sign-in marks it. This guards spending against Pi's choices, not against a person: anyone who can steer can pick a session's model, and Pi, which runs commands, can reach Pi's sign-ins and Pi Pocket's files like anything else on the machine.
- **Linked sessions** (Agent Teams, off until the owner turns it on) widen what prompt injection can reach. A session that read something hostile (a page, a file, an issue) can pass it on to the other sessions of its team in a message, and a message makes Pi work in the target for the person Pi worked for in the sender, with that person's access, in a session where other people may have written. Pi is told to take a linked session's message as a request, not as an order from a person, and to do nothing destructive or with credentials only because one asks; that is guidance to the model, not a boundary. A message is fenced, and a team stops after 20 messages without a person, at the starting session's spend limit, and at 10 sessions; a link gives no access to a session someone cannot already see.
- **Managed handoff workflows.** Agents can prepare briefs, record code-bound completion and recommend successors; only a human activates a handoff. A predecessor permanently loses local write capability across filesystem operations, shell execution and descendant agents; verified read-only local inspection remains available. The mandatory core gate is independent of Lancet Guard. Managed shell commands run offline under macOS `sandbox-exec`; they cannot download dependencies, access network services or run HTTP/server tests. Shell execution fails closed on unsupported platforms rather than falling back to unrestricted execution. Browser, artifact and unknown extension tools are blocked in managed agent workflows because they could bypass publication approval. Existing artifacts and runnable reply previews are also denied in those conversations, including execution on a viewer’s device. An active Pull thread has a separate constrained `pull` adapter for configured Git remote fetches and explicit GitHub PR/issue reads. It is not an online shell: Git's network phase uses an app-created bare staging repository without checkout hooks/config or credential helpers, then imports only remote-tracking branches through the offline sandbox. File remotes stay offline. GitHub reads use allowlisted built-in commands against github.com; arbitrary API calls, aliases, templates, scripts and mutations are unsupported. External content remains untrusted. A Publish thread uses the separate `publication` tool for supported Git/GitHub CLI actions, with human approval bound to the command, checkout, destination and relevant executable inputs. An interrupted or failed external operation remains uncertain until a human reconciles it; another handoff cannot erase that receipt. These restrictions control the normal agent execution path, not the administrator or trusted server extensions, which still execute with server rights. Unrelated Chats retain their existing execution behavior. See [handoffs](docs/handoffs.md).
- **Plan mode** keeps Pi to planning; it is not a boundary. Programs that people configured to run on their own, such as a git diff driver, run as they would for anyone.
- **Drop-in extensions** in `~/.pi-durable-app/extensions/` run inside the server with the owner's rights. They stay off until the owner turns them on. One with a browser module also runs code in the app's own page, with the rights of whoever's tab loads it: the owner's alone unless the module opens it to others (never to someone invited to one session). The page's content security policy keeps that code from loading scripts and styles from another site or fetching from one, but code in the page could still send data out in other ways (navigating the page elsewhere, for one): turn on only browser modules you trust, as with the server part. What a module's route throws with `web.error` reaches everyone who may use that route as it is; anything else it throws, only the owner reads. Every file of a web type (`.js`, `.mjs`, `.css`, `.json`, images, and `.woff2` fonts) in a browser module's folder can be read by everyone the module is for. A module's conversation command is offered to everyone who can steer that session, people invited to only that session included, and its handler runs with the owner's rights: treat its arguments as untrusted, and check who runs it. A global command is the owner's alone.
- **The extension gallery** (Menu → Extensions → Find extensions) installs drop-ins other people wrote, so what it installs has the owner's rights once turned on. It reads its index strictly, downloads only over https from each entry's pinned commit, refuses a file whose SHA-256 differs from the entry's, keeps file names inside the drop-in folder, and installs everything off; updates are never automatic. The index's checks and its maintainers' review lower the risk, but do not remove it: read the code (or ask Pi to review it) before you turn one on. Only the owner can use the gallery. A theme from the gallery is CSS, fonts, and images that the owner chooses to install. Pi Pocket checks it as every theme folder before it is in place, so it cannot load anything from other servers, nor the app's own addresses, and it runs no code. It can still hide or relabel parts of the app, approvals too: install only themes you trust.
- **Pi provider packages** are owner-selected trusted executable dependencies, not sandboxes. Discovery reads metadata only; adding/selecting/updating/enabling packages requires explicit trust confirmation. Coop installs exact releases with npm scripts disabled in separate retained trees and activates them only after restart, through isolated child workers. Isolation separates Pi settings and concurrent provider state, not filesystem/network rights or credential access; Lancet Guard does not inspect provider code. Package responses contain public settings, not keys or secret headers. Only supported API-key chat profiles are exposed; SSO, command credential helpers, MCP/skills and embedded tool loops are not implicitly enabled. A startup failure without a usable retained release holds all Durable progress while owner recovery controls remain available.
- **Replies are untrusted.** Anything Pi reads can steer what it writes, so the app page loads nothing from other sites, and replies cannot contain forms, scripts, or styling. Artifacts run in a sandbox with no access to the app. An HTML block in a reply is previewed in a frame of its own with its scripts off and a policy that loads nothing, not even from the app; tapping **Run** runs it as an artifact runs, with scripts and the network but no access to the app, so a page Pi was steered into writing could then send what it shows elsewhere. SVG blocks show as images, which run nothing. Managed handoff conversations disable executable artifacts and **Run**, and preview-frame requests must identify an accessible, unmanaged conversation or the owner-only private context.

Problems within these limits are bugs we want to hear about: for example, a viewer making Pi act, a session-scoped person seeing another session, or a reply reaching the app's cookies or API.
